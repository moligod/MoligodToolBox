## 旧实现审阅与重写范围

只读审阅 .reference/DF-AutomatedTool 的 WPF 主窗口执行器、脚本数据与 OnnxOcrHelper。旧流程包含 A/B 窗口、鼠标/键盘、OCR、变量、表达式与正则、If/ElseIf/Else、循环、标签跳转、延时与定时。OCR 实际委托 Python 子进程与模型；执行器和界面紧耦合，Thread.Sleep 等待不便及时取消。旧网络适配器操作本身未进入其脚本序列化。

新版使用强类型 schemaVersion=1 脚本，启动前编译控制流与表达式，Windows 原生输入和离线 PP-OCRv6。没有复制 WPF/Python 运行时，也没有兼容旧项目脚本格式。网络适配器管理、任意 shell/程序执行不纳入游戏工具执行器。

## 限制与取舍

OCR 使用 Rust 原生 PP-OCRv6 small/tiny，检测预处理、文字框提取、透视裁剪和 CTC 解码均在 Rust 中实现。全局识别方式为 CPU（CPUExecutionProvider）、A 卡（DML，选择 AMD 适配器）、N 卡（TensorRT RTX，需要 RTX 30 系或更新显卡及兼容驱动）。设置自动保存，执行器创建时快照；旧 gpu 值按 DML 映射到 amd，旧动作 ocrModel 保留读取但不覆盖全局选择。按需启动的 moligod-ocr.exe 是 Cargo 编译的 Rust 程序，无 Python/OpenCV/NumPy 运行时；推理使用厂商原生 DLL。运行时离线、不下载模型，缺少显卡或资源明确报错，不将失败会话静默降级到 CPU。取消和超时会回收子进程；RTX 首次编译可能较慢，暂不使用磁盘缓存，进程内复用会话。构建准备见 modules/ocr/README.md。截图读取前台可见客户区域，被遮挡、最小化、独占全屏或受保护画面可能不可用。

脚本最多 1000 步、128 变量、一次运行最多 100 万执行步和 24 小时；表达式有长度/深度限制，等待可取消。截图最多 1600 万像素；模板最长边 512 像素，匹配最多 5000 万像素比较并检查取消（这不影响准星自定义图片尺寸）。模板匹配使用 RGB 差异和透明遮罩，适合固定像素素材，不是缩放旋转识别。

高级 JSON 可设置随机延时、总重复/运行上限等所有脚本字段。当前步骤列表的逐项编辑通过高级 JSON；不宣称已有录制器、可视化所有参数编辑或旧脚本直接导入。

## 多任务、动作组与双区域 OCR · 2026-09-28

任务管理区只填写任务名称与每次任务间隔（毫秒）。点击下方任务行选中，上方回填名称/间隔，动作编辑器显示该任务脚本；选中行高亮，可用 Enter/空格选择。切换保留各任务未保存的草稿，新建任务重置新任务草稿。列表独立运行/停止，最多4个并发，可展开每项变量和最近日志。自动运行时按间隔重复脚本，运行上限与取消仍生效。

动作列表可连续选择多项成组并拖动排序；组内步骤在执行前有界展开。按住拖动动作填写起点/终点与时长，释放/停止会松开鼠标按键。滚轮可填坐标与增量。成组OCR在同一截图上依次画A/B两个矩形，返回 `{A,B}`；“取成组OCR值”动作选择组变量与A或B写入另一变量。单个OCR仍是一块区域。

新建、保存和归档位于“我的任务”标题旁。归档会停止该任务，将原文件移入本地tasks/trash并从列表移除，不是永久删除。任务行右侧分别显示运行、停止，按该行任务状态禁用不能使用的按钮；上方不再显示运行当前、停止当前、运行全部或停止全部。未保存草稿需先保存后运行。

## 代码样式动作序列 · 2026-10-05

上方左侧选择任务，右侧选择动作分类、操作并填写参数，点击“添加动作”；下方为全宽代码样式动作序列。动作行带行号、括号、分号及缩进线，组/循环/条件可点击箭头折叠，也可全部展开/折叠。折叠只改变显示，不改脚本内容；同一编辑操作后的容器排序保留折叠状态，不写入持久化数据。

固定动作名、参数名及语法符号是只读文本；框内数值、文字、窗口等参数可直接修改，数值为橙色、文字及选项为绿色，动作名按类别高亮。合法输入即时写回当前草稿。OCR区域展开后可修改边界；按键组合沿用只读展示及上方动作表单。非零结束步骤延时也展示为可编辑参数。

拖住行标题或握柄，可放到行间插入位置调整顺序，或放进组/循环/条件内部；整个容器连同内部步骤一起移动，禁止放入自身。握柄聚焦后可用上下方向键排序。勾选连续顶层动作可成组，删除容器会删除内部动作。选择插入位置后，上方新增动作插入那里；循环/条件自动补结束，条件底部可新增分支。折叠当前插入位置所属容器时，新增位置移到该容器后，避免插入不可见区域。

单脚本运行时修改/排序/添加仍禁用，可展开或折叠查看；执行到折叠容器内部时自动展开祖先并高亮当前步骤。导入仍为schema1脚本，导出不含折叠状态；现有任务文件与Rust引擎不变。无效/不完整控制流保留原始步骤及警告，可在高级JSON修正，不静默丢弃。

## 新手使用流程 · 2026-10-08

保留上方任务/添加动作两列、下方代码序列。顶部提供可收起的三步指引：给任务起名、添加动作、检查后运行。新建任务和首次进入都从空序列开始，不自动加入备注或等待；可以先添加等待练习，空序列禁用检查和运行。

常用入口为鼠标点击、按键、等待、识别文字，切换入口会同步分类和参数，不会立即添加或执行。每种动作显示用途和填写说明；OCR提示截图画框及测试结果，点击提示按住拖动取坐标。窗口 A/B 是对已打开软件的引用，新增槽位不启动软件。未绑定的目标可点击提示打开窗口选择；保持动作级窗口设置。

任务间隔仍以毫秒保存，旁边实时换算为秒。任务列表显示中文状态、秒数及“未保存”，草稿改名即时同步。保存任务包含下方序列；运行当前序列与任务列表重复运行入口分开。紧急停止快捷键始终显示在序列运行区。

单独脚本保存、导入导出、JSON和变量查看收进“脚本文件与高级设置”。高级功能、数据格式及Rust执行语义不变，不增加引导持久化、网络、依赖或后台工作。

### 窗口与 OCR 框选入口调整 · 2026-10-08

窗口标签右侧的 × 删除该槽位，最后的 ＋ 添加槽位；软件下拉框右侧 ↻ 刷新系统窗口列表。仍被动作使用（包括动作组内引用）的槽位不能删除，至少保留一个槽位。

选择“读取屏幕文字”后进入“截取窗口并框选区域”，在独立截图窗口标题旁选择“单个区域”或“成组 A / B”。成组按顺序画 A、B 两个框后确认；切换方式会清空旧框。确认后主页面动作类型和坐标一起更新。截图和 OCR 结果子窗口统一深色标题栏，提供拖动、最小化、最大化/还原、关闭。

## Blockly 动作编排 · 2026-10-25

当前界面以顶部任务管理、模型设置、运行日志、动作、快捷键设置工具栏为入口，下方使用 Blockly。点击“动作”中的按钮添加积木；选择循环/条件/分组再添加可放入其内部，也可以直接拖动到吸附位置。简单文字、数值和条件在积木内编辑；鼠标、OCR、模板匹配和截图用齿轮打开原设置窗。

单选动作后点右侧“+”即可写注解。已有注解可直接点击修改，清空后点击别处即可移除。注解随该动作保存、移动和复制，平时以淡色小字显示在右侧。

IF 底部可以加“否则如果”与“否则”；删除分支前需移出内部动作。右键菜单支持复制、折叠、删除，Ctrl+Z 撤销，画布支持平移/缩放和拖动边缘滚动。运行期间禁止修改。齿轮或右键“延时 / 注解”中的动作参数可改注解、前延时、随机延时，以及条件分支/结束步骤元数据；纯分组没有执行延时。

所有需要执行的积木必须接到“任务开始”。游离积木会阻止保存、导出、运行和任务切换，重新接好或删除后继续。原 schema1 脚本和 schema2 任务继续使用，Blockly 只负责编辑并转换回原 Step[]，执行仍通过 src/api.ts 交给 Rust 模块；不会生成或运行 Python。旧文件不会自动重写，模型全局设置、DPI缩放和任务循环开关沿用原行为。

开发检查：npm test、npm run build；原生兼容与安全动作执行检查先运行 npm run modules:build，再运行 node scripts/verify-blockly-native.mjs。该脚本使用独立 target/blockly-native-* 数据目录，只执行变量/循环/条件/断言/等待，不发送鼠标键盘或调用OCR。

### 找到图片后点击，以及新增动作 · 2026-10-27

1. 添加“查找图片”，选择窗口、图片和查找范围，勾选“保存图片位置”，保存到变量 result。
2. 添加“鼠标操作”，选择同一窗口和“鼠标点击”，将“点击位置”改为“位置变量”，填 result。找到后点击图片中心；没找到会保存 null（空），直接使用空位置会停止，不会乱点。
3. 如果要等图片出现，把“查找图片”放进“等待条件”内部，条件填 result != null，并设置最多等多久、每隔多久检查。条件满足后才继续后面的点击；超时停止任务。若找图未勾选保存位置，仍保存 true/false，此时判断用 result == true。

鼠标键盘增加“按住按键”“松开按键”。例如按住 W → 等待 2 秒 → 松开 W；任务结束、取消或报错时会释放本任务仍按住的键。

鼠标键盘现将点击、按住和松开合并到同一个按键积木，通过下拉框选择动作并录入按键。点击模式可设置持续时间；按住和松开不需要持续时间。已有任务继续使用原有动作及参数。

基础操作增加“运行任务”：选择一个已保存任务，执行一遍后继续主任务，双方共用变量。调用时不采用子任务的循环次数和启动延时设置。互相循环调用会在开始前报错。跨电脑导入脚本后，需重新选择本机对应子任务。以上动作继续由 Rust 执行。

在“基础操作”拖入“定时启动”，输入本机的 24 小时制时间，例如 `07:30:15`。想让整套动作到点再执行，就把它接在“任务开始”的下方，保存并点击“运行”。执行到该积木时会等待目标时间，当天时间已过则等到次日。等待期间可停止，并计入任务的最长运行时间。含该动作的脚本使用版本 5。

### 动作积木多选

单击动作后，Shift 单击同一块堆中的另一动作，选中两者之间按画面顺序展开的动作，包括条件等容器及其内部动作；Ctrl 单击可单独添加或取消。跨块堆的 Shift 单击从新位置开始，选择仅为当前画布状态，不写入任务。按住任一已选动作可一起拖动，选中容器时保留其内部动作；绿色短线表示可吸附的位置，Esc 或在画布外松开取消。预览绘制前12个最外层动作及被抓住的动作，其余仍会一起移动。多选拖动暂不支持靠近边缘自动滚动画布，跨屏移动前可先调整缩放或滚动位置。松到画布空白处会形成未连接的积木堆，需接回任务后才能保存或运行。多选尚不提供批量删除，Delete/Backspace 在多选时被拦截，避免误删一个动作。输入字段和按钮保持原操作。

### 组件库

在积木画布内按住Ctrl并滚动鼠标滚轮，以鼠标位置为中心放大或缩小，缩放范围为30%–150%。普通滚轮滚动画布，左下角的加减按钮也可调整缩放。

在画布选中一个或多个动作后，右键其中一个已选动作，点击“保存成组件”并输入名称；按 Shift 或 Ctrl 可多选。组件保存为包含所选动作的分组，条件、循环及其内部动作一并保留；不连续多选按画布顺序组合。点击组件名称可修改名称，按住标题上下拖动可调整组件顺序，名称和顺序保存在本机。组件库中的组件默认收起，点击名称右侧“展开”查看并按住拖到任务中；再次点击“收起”隐藏预览。原动作和库中组件不会随副本一起改变。组件保存在本机，可点击组件名右侧的“删除”；已放入任务的副本不受影响。保存和放置均要求任务有有效屏幕缩放，不同缩放之间自动换算组件副本中的坐标。组件库为空时中央显示右键保存和多选提示。

每条组件名称右侧的“导出”将该组件的动作代码复制到剪贴板，可直接发送给他人。组件库顶部的“导入组件库”打开代码输入弹窗，粘贴收到的完整代码后点击“导入”，即追加到本机组件库。代码包含名称、动作参数和缩放，沿用schemaVersion 1的JSON格式，同名项保留，重复标识自动分配新值。版本或内容无效、合并后超过100项或1MiB时会提示失败并保留原库，输入内容可继续修改。代码中的模板图片使用原templateId引用，跨电脑使用需另外准备相应模板图片。

组件库保持90%的固定显示比例。展开的组件各自提供底部横向滚动条，拖动滚动条可查看超长动作内容。组件面板最多占编辑区总宽度的四分之一，标题过长时显示省略号，悬停可查看完整名称。

“设置变量”积木位于“条件与取值”分类，可与数字、变量和计算积木组合，将计算结果保存到指定变量。

### 识别结果参与数字比较

读取文字保存的是文字，包括勾选“仅保留数字”后的结果。使用“变量”的数字类型时，有效的数字文字会按数字读取并参与比较，原变量中的文字保持不变；空结果、无效数字或非有限值仍会报类型错误，不会自动当作零。

读取完成后可在左下角“日志 → 识别日志”查看保存的变量。数字取值失败时，错误会区分空文字与无法解析的数字文字，方便核对运行时的实际结果。

任务运行期间，同一目标窗口的 OCR、截图和找图复用窗口捕获会话；任务结束、窗口切换或出错时释放。Windows 的捕获提示边框在会话期间可能持续显示。
