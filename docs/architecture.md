## 定时启动积木 · 2026-11-20

脚本版本 5 增加 `scheduleStart` 动作，时间以 24 小时制 `HH:mm:ss` 写入。执行到此步时由 Windows 驱动读取本机日期和时间，锁定今天或次日的目标。等待沿用现有任务取消令牌和最长运行时限，每次睡眠最多一秒，临近目标时按剩余毫秒等待。状态沿用 `scheduled`，等待期间显示目标时间，到点后继续当前脚本。只在执行该动作时读时钟，无新增调度服务、IPC 命令或启动轮询。[Windows 本地时间 API](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getlocaltime)

加入积木标题与时间字段后，按需 Blockly 及媒体构建实测 798.1 KiB，预算由 798 KiB 调整至 799 KiB，主资源仍按 254 KiB 检查。

## ADR-001：模块化单体，依赖朝核心收敛

```text
TypeScript UI → src/api.ts → Tauri commands
                              ├── moligod-core
                              └── moligod-storage → moligod-core
```

核心只依赖 serde；不导入 Tauri、Windows、数据库、网络客户端。存储负责文件格式与落盘，桌面层负责组合与生命周期。
CI 检查 crate 依赖白名单及前端 Tauri 导入边界。白名单变更必须审查。
crates/crosshair 作为独立 Windows 准星适配器，使用具体资源所有者封装窗口、热键和 GDI 句柄；不创建泛化平台 trait 集合。
前端采用 TypeScript + 原生 DOM，未来复杂度需要时可以换框架，IPC 适配和核心不变。

## ADR-002：不运行就是不占用工具资源

启动时只创建主窗口、托盘与配置状态；没有工具工作线程、截图、OCR、定时更新和网络请求。
TaskSlot 只在 start 时创建线程，重复启动拒绝；停止先取消再 join，完成回收后才允许重启。
Cancellation 的条件变量能唤醒长延时，不需要高频轮询。
这是**协作取消**：工作函数必须使用有界 I/O 并观察取消。它不能强制终止阻塞的外部库。
未来不可控 OCR 推理或可能卡死的第三方任务放入按需工作进程，另设超时、kill、wait 与输出上限。
TaskSlot 由自动化工作进程使用；宿主停止与回收在后台执行，已补独立模块退出与失败路径测试。

## ADR-003：先保护用户数据，再考虑兼容便利

配置 schemaVersion 从 1 开始。读写双方校验参数；拒绝未知字段及未来版本，防止旧客户端丢失新字段。
设置存储限 64 KiB；同目录临时文件写完 sync_all 后替换，避免应用中途退出留下半截 JSON。
保存前原子更新上一版备份；备份失败则不替换主文件。
桌面单实例 + 进程内锁保证本应用单写者。手工修改文件和另一个程序写入不属于并发协议。
原子替换不是断电零丢失保证；备份也不能代替用户备份。
本项目配置已升级至内部格式 3，设置迁移保留原始备份与原有按键语义，并有回归测试。不会读取旧 Python 工具注册表或修改旧项目数据。
2026-09-28：准星参数改为自动保存，前端以同一个配置所有者合并窗口设置与准星设置，写入采用一个在途请求和一个最新待写值。返回的旧保存结果不会覆盖较新的编辑草稿；实时绘制与保存分别限流，工具停止也能保存配置。持久化仍走既有后台命令和原子存储，没有启动轮询。

## ADR-004：桌面权限收紧

只加载打包本地页面；CSP 禁止远程脚本、嵌入页面和对象。
无 shell、任意文件访问、HTTP 插件权限。自定义命令均校验 main 窗口标签，准星命令只接受强类型配置和有限大小图片数据，图片读取限于应用管理目录的哈希标识。攻略入口通过 Rust opener 打开固定的 https://moligod.com，不接收 URL 参数，不向前端开放通用 opener 权限；关闭自动捕获 JS 链接，仅在用户点击时执行。
无边框标题栏仅给 main 增加 close、minimize、toggle-maximize、internal-toggle-maximize、start-dragging 五项窗口权限，不启用 core:default。前端窗口操作仍集中于 api.ts。
另开放 main 事件监听/解除监听，用于准星状态推送；不轮询运行状态。
Tauri 自定义命令默认暴露给应用本地 WebView；仅收紧插件权限并不代表自定义命令不可调用。
添加窗口或命令时必须重新审查授权范围。用户导入 JSON 始终作为数据解析，不插入 HTML。
界面下载预设只含准星字段，不含窗口设置与本机路径。

2026-11-20：按用户要求，Windows 正式版主 EXE 内嵌 `requireAdministrator` 清单，系统在应用初始化前请求管理员授权。用户取消时应用不启动。Tauri 开发模式沿用默认清单，可从普通权限终端启动本地调试流程。

v2.0.1 将 NSIS 正式发行切换为全机安装，路径固定为 Windows 识别的 `Program Files\MoligodToolBox`。宿主在创建 WebView 前验证自身和随包模块目录的最终路径，正式版只启用随包模块。模块及 OCR 子进程以其程序目录为工作目录，内置更新把已验证的安装程序暂存在受保护的安装目录。开发版仍支持本地模块覆盖。任务、图片和配置继续按用户保存。旧版是每用户安装，迁移时新版安装器保留旧文件，避免以管理员权限运行旧目录内的卸载程序。

## ADR-005：性能预算与可复现验证

应用维护锁文件、固定 Rust/Node 版本、Windows CI 和前端未压缩 150 KiB 上限。
无第三方字体、图片/CDN、图标库和组件库运行时。
进程内存必须包含 WebView2 子进程；EXE 大小和前端体积不能替代实际常驻占用。
Rust release 先使用 opt-level=s、thin LTO，依据后续运行测试选择优化方式，不假定体积优先总是最快。

未来游戏、工具、预设使用稳定标识和版本化数据关联。联网内容模块故障不影响本地工具。

## ADR-007：可独立分发的工具进程

为支持未来用户点击下载工具，准星和自动化改为独立 Rust EXE，主程序不链接工具执行引擎。共用版本化 stdio 协议及模块宿主，状态以事件推送，工具按需启动，停用回收。原有 UI 和配置入口保留。

当前完整安装包自带模块；用户目录可发现单独安装的版本。模块版本与平台版本分离，通过协议兼容性约束。此轮不实现网络下载，保留可复用的安装后运行边界。独立 EXE 避免 Rust 动态库 ABI 兼容问题，也把 OCR/输入故障与平台隔离。

自动化重写采用 Windows 系统 OCR、受限表达式解释器及可取消运行器。减少分发的 Python/模型依赖，但识别语言和效果依赖 Windows，必须明确验收边界。详细清单、生命周期及后续签名下载要求见 modules.md 和 automation.md。

2026-09-27 窗口绑定扩展：Slot 从 A/B 扩展为 A–Z，保持 schema1 原字符串编码，原有脚本可读；新版 UI 动态管理标签，仍由引擎统一检查绑定与窗口身份，不改 IPC 传输边界。至少保留一个标签、禁止删除仍被脚本引用的标签；不持久化系统窗口句柄。

## ADR-009：原生工具子窗口 · 2026-09-28

工具编辑器留在主内容区，截图框选与OCR测试结果使用独立顶层WebviewWindow，Windows owner设为main，不是嵌入主WebView的dialog。主窗口关闭/隐藏到托盘时关闭子窗口；关闭子窗口不执行平台退出逻辑。

独立auxiliary.html入口共享api.ts调用边界，子窗口只获得事件监听和关闭权限；状态/提交命令校验当前会话窗口标签，前台编辑页仍打开才允许回填。主进程验证选区边界并只回填已知字段。每次打开使用唯一label，取消/切页清除状态，迟到结果不能重新显示已关闭窗口。最多保留一个工具子窗口，避免常驻多个WebView。

## ADR-010：本地任务与可编排动作 · 2026-09-28

参考 WebTrade 的任务配置、动作分组及A/B成对ROI，继续使用 moligod 独立工具进程。任务是版本化本地数据，窗口绑定是运行期能力，不保存句柄。一个任务一个可取消运行器，最多4并发；前台输入串行、截图按需求单次读取新帧。输入快捷键在活动运行器间共享，最后一个运行器退出时释放注册。旧脚本schema1字段保持兼容，新动作以扩展枚举加入。详情见automation.md与verification.md。

## ADR-011：工具标签与编辑器生命周期 · 2026-09-28

工作台和已打开的工具标签分开；工具标签在本次会话内去重保留，不在启动时恢复工具或预加载原生模块。切换标签/返回工作台发deactivate，保留表单、未完成草稿与已打开的编辑器能力，只取消临时按键录入、截图选择等交互；显式关闭标签发close，复用原有空闲模块release。运行中的准星/自动化任务由自己的开关停止，关闭标签不代替停止工具。

关闭后快速重开先等待上次release，编辑器会话代次丢弃已关闭会话的迟到初始化结果。准星开启/关闭入口位于工具页，卡片保留配置入口与运行状态。返回工具箱只切换页面，不关闭已打开的标签。不引入新的原生命令、后台轮询或持久化格式。

## ADR-012：任务元数据与动作窗口分离 · 2026-09-30

任务只配置名称、每次执行间隔及动作脚本；窗口依赖归属每个动作的target，由Automation启动时统一校验编译后的动作目标。删除TaskManager及前端的额外单一窗口源前置条件，纯等待任务不要求窗口，同一脚本可引用不同槽位。任务选择直接放在列表行，选中回填配置及脚本；草稿按任务保存，异步读取使用选择代次避免迟到回复覆盖新选择。

任务文件升为schemaVersion=2，脚本schemaVersion=1和动作target编码不变。明确读取v1结构并在内存中转换；读取不改磁盘，首次保存前保留原字节为.json.v1.bak。未知字段、损坏文件、未来版本及标识不匹配仍拒绝覆盖。固定v1夹具及跨进程双任务测试验证数据保留和窗口依赖边界，不新增原生命令、网络或后台轮询。

## ADR-013：积木编辑视图与现有脚本解耦 · 2026-09-30

动作序列以前端树形积木呈现：普通动作是叶节点，动作组、循环、条件和分支是容器。automation-block-model负责将schema1的平铺控制标记及已有动作组转成视图，并完整写回原格式；开始/结束、各分支、延时、窗口目标及其它参数保留。不改变Rust枚举、执行器、IPC或任务文件版本。无效/不完整控制流保留原始步骤并显示警告，不删除无法识别的内容。

移动对象是完整积木子树，禁止自嵌套；选择连续顶层积木成组同样保留完整控制结构。automation-block-editor负责DOM、指针捕获、槽位、键盘排序、参数及执行位置标记；合法参数输入即时同步JSON且保留焦点，结构变化才重绘。循环/条件的新建自动补闭合，分支在容器中添加。继续保留JSON导入/导出；按后续用户要求，添加步骤与动作积木各占50%，窄窗口上下排列。

使用现有HTML/CSS/TypeScript实现，不增加Blockly或其它框架依赖，前端预算仍为150KiB。图形只是一层编辑适配，运行仍交给独立Rust模块；不在启动时恢复执行、截图或OCR。

## ADR-015：按意图选择动作与双视图 · 2026-10-08

后续用户实测认为添加说明仍不足以让新手使用。初始页不展示参数表单，先提供常见意图卡片；选择后显示必要设置，坐标、延时等支持逐步展开。默认序列用自然语言描述每一步，按需展开修改；保留代码视图，切换只改变DOM可见性，不重建脚本、不重置折叠和插入位置。空状态提供仅等待1秒的示例，不自动运行或覆盖已有任务。时间输入以秒呈现，在视图边界转换为原有整数毫秒，不迁移文件或改变引擎。

## ADR-016：选区内切换 OCR 方式与子窗口标题栏 · 2026-10-08

窗口管理改为标签内删除、末尾新增和软件选择框旁刷新；删除校验覆盖嵌套动作组并至少保留一个槽位，绑定仍只在本次会话中保留。取消重复的绑定提示，不改变脚本和任务格式。

OCR 截图请求显式传入 allowRegionPair，仅 region/regionPair 会话允许在同一截图上切换单区域和 A/B。切换清空选区，提交同时携带实际 mode；主进程校验会话、允许的模式、A/B 完整性和像素边界，再将模式与选区回填，父编辑器同步动作类型。点击取点、图像匹配和保存截图不获得切换权限。OCR 结果窗口仍只展示结果。

辅助窗口使用无系统装饰的深色标题栏，保留独立 owner/main 关系；权限仅新增对子窗口本身的最小化、最大化和拖动，不增加主窗口控制或执行引擎权限。原生调用仍统一位于 api.ts。为保持 155KiB 预算，删除已无 HTML/TS 引用的旧工作台说明、预设行和路线图样式；不增加依赖。

## ADR-017：从插入位置直接创建动作 · 2026-10-13

## ADR-025：纯 Rust OCR 与三种执行后端 · 2026-10-22

原225MiB预算适用于旧Python+DML方案，不能涵盖新增RTX资源；新构建同时带三后端，分别计量基础库与N卡库，最终体积以verification.md为准，不再把厂商核心库宣传大小当作完整安装大小。

RTX动态形状回归：RTX5080上固定图片在动态维度会话中出现空检测/空识别，不能归因于缓存单一因素。N卡分支固定batch=1、检测960×960、识别48×3200，按原缩放结果补归一化零值，坐标按未补边尺寸换算；关闭ORT图优化、memory pattern、磁盘缓存和CUDA图捕获。CPU/DML保持原动态尺寸。该选择优先保证结果正确；存在首次编译延迟及补边显存开销，速度必须实测，不能笼统声称比DML快。

2026-10-23 发布精简：锁定的 small/tiny 模型在隔离运行库中无需可选 tensorrt_plugins.dll。准备脚本只从 RTX 包提取 EP、核心和 ONNX parser 三个 DLL；保留独立 ORT、CUDA runtime 和许可证。准备与模块资源复制精确清理旧插件副本，构建拒绝含该插件的源资源，防止增量打包带回。此结论限于当前模型和版本，更换模型/RTX 时需重新验证；不删除必需的 onnxruntime_providers_nv_tensorrt_rtx.dll。

官方组件目录采用schemaVersion 1及小写字母/数字/连字符标识，拒绝路径穿越、重复ID、未来版本及过多条目。组件动作代码走现有Blockly验证、组件导入和原子追加，导入保持用户确认，运行继续由任务入口控制。弹窗代次在关闭和销毁时失效，运行锁阻止下载完成后新增组件。

版本采用SemVer比较，排除草稿和预发布，更新红点与可访问名称同步。安装前重新核对最新版本，按确认版本标签获取latest.json，限定安装包地址为官方仓库该标签下的NSIS资源，并由Tauri updater验证签名。网络下载在异步任务执行，安装及工具资源回收在后台执行。公钥进入应用配置，私钥保存在忽略目录，通过Actions Secrets发布签名更新。

新增功能主资源首次实测252.0KiB/254KiB，按需Blockly及离线资源796.6KiB。官方组件双按钮与导入桥增加约1.1KiB按需资源，将按需预算从796调整为798KiB，主资源预算继续为254KiB。新依赖限于桌面适配层，采用reqwest进行有界GitHub请求、semver比较版本及Tauri官方updater完成签名安装。

用户随后选择以旧DF-AutomatedTool仓库承接重构版，并将其重命名为moligod-toolkit。原仓库实际最新Release为v1.1，附件为旧程序ZIP及动作JSON，缺少新版latest.json。版本检测先检查更新清单附件，再比较SemVer，使旧程序发布记录可以继续保留。固定历史Release夹具覆盖该场景，组件目录和更新端点沿用正式仓库名称。

### 代码审查高优先级修复 · 2026-11-19

按 Codex（gpt-6.2-astra，max）只读审查结果修复六项高优先级问题，均未新增依赖、启动任务或 IPC 方法，持久化 JSON 外形不变。

跨任务前台输入锁改为可取消等待：等待者每 10ms 检查自身取消信号，停止等待中的任务不再阻塞在另一个任务的长按上，也不会因 30 秒 IPC 超时而终止整个自动化模块。持有者语义不变。

无字段动作 else、endIf、endLoop、break、continue、endWaitUntil 由 Rust 单元变体改为空结构变体。Serde 对内部标签枚举的单元变体会忽略 deny_unknown_fields，改动后带未知键的任务读取与保存都会被拒绝并保留原文件；磁盘格式仍为 `{"type":"..."}`，无需版本迁移。

module-host 每个模块会话增加独立 stdin 写线程，调用方只排队帧并等待写入确认，同一截止时间覆盖写入与回复。模块停止读取输入时调用按超时返回而不是持锁无限阻塞。会话释放时先关闭写队列，宽限期后 TerminateJobObject 终止整棵进程树，再 join 写线程和读线程，避免继承管道句柄的子进程使 join 挂起。module-protocol 新增 encode_frame，帧格式不变。

截图只写入盘符路径（含 `\\?\C:\` 形式）；UNC（`\\server\share`）、`\\?\UNC\` 与设备路径在运行时拒绝，原生文件夹选择器同样拒绝，编辑器对导入的网络位置显示问题提示。已保存的网络位置任务仍可打开修改，不会被改写。映射驱动器需本机预先设置，继续可用。这是对 ADR 截图保存位置的收紧，替代“任意绝对路径”。

找图保存的位置值增加捕获窗口的 hwnd 与 pid。点击使用位置变量时，引擎经 Driver::expect_window 传入该身份，原生驱动与本次实际解析的窗口核对，槽位被 SetWindow 换绑或句柄被其他进程复用时拒绝点击。位置值只存在于运行期变量，缺少身份的值要求重新找图。

任务多轮之间的间隔等待使用任务总截止时间，到达 maxRunSeconds 立即以“达到脚本最长运行时间”结束；驱动随之释放，仍按下的按键由 HeldKeys 释放。

### 代码审查中低优先级修复 · 2026-11-19

按同一份审查修复其余十一项，未新增依赖、启动任务或后台网络。IPC 只新增宿主发给工具窗口的 tool-window-visibility 事件，没有新命令；持久化格式不变。

任务保存返回时，只有当前画布与提交时的快照一致，才用已保存版本重绘并删除草稿。保存期间发生的编辑留在画布上，并记为该任务的未保存草稿。

独立工具窗口的标题栏关闭仍然只隐藏窗口。宿主隐藏前向该窗口发出 visible=false，页面据此执行原有的关闭流程：保存草稿并发送 release，空闲模块随之退出，运行中的任务和准星不受影响。再次打开时宿主发出 visible=true，页面重新激活并按需打开模块。

宿主任务状态缓存在归档成功后删除对应条目，模块断开时在标记失败并通知前端后清空。模块回复归档前已 join 运行器，最终状态事件先于回复处理，迟到事件不会把条目写回。

OCR、快捷键和任务排序三个设置文件的 .bak 改为与主文件相同的同目录临时文件加原子替换，逻辑抽到 crates/automation 内部的 atomic_file 模块。重读原文件时沿用各自的大小上限，超限则不覆盖已有备份。

tauri-plugin-updater 2.12.0 读取 latest.json 时没有大小上限，也不能注入外部字节。安装前先用现有的 1 MiB 有界读取器下载同一标签的 latest.json，插件解析结果必须与它完全一致，否则放弃安装。版本绑定、下载地址校验和签名校验不变。插件自身的读取仍无上限；若同一 Release 资源恰好在两次请求之间被替换成超大文件，不分叉插件就无法排除。

刷新截图开始时清空 OCR 测试结果，识别回复只在发起时的截图仍为当前截图时显示。预览截图和 OCR 测试完成后，只恢复发起请求且仍可见的窗口的焦点，不再唤起已隐藏到托盘的工具箱主窗。

滚轮增量改用 -1200..=1200 区间检查，i32::MIN 不再在 abs() 处溢出。行内框选的区域端点按边界处理，可以取到图像宽高，拖过右下角即可选入最后一列和最后一行；点击、拖动和滚轮的点仍限于最大像素下标。

module-protocol 的服务循环只在协议匹配且 shutdown 处理成功后退出。协议版本错误或处理失败的 shutdown 只回复错误，模块继续服务。Windows CI 增加 value_blocks 集成测试和桌面宿主 moligod lib 单元测试。
