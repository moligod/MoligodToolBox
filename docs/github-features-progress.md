# GitHub 官方组件与更新进度

## 目标与约束

- 组件库顶部新增“获取官方组件”，从 moligod/MoligodToolBox 的 official-components 目录读取目录和动作代码，用户选择后复用现有组件导入。
- 访问失败显示“无法访问官方 GitHub 仓库”。
- 主窗口版本号作为更新按钮，启动时单次检查 GitHub 正式 Releases，新版本显示红点，点击确认后下载并安装签名更新。
- 本轮采用稳定模式，覆盖远程数据、异步关闭/重试、版本比较及更新签名边界。
- 用户已要求将正式仓库改名为MoligodToolBox，同步地址并上传源码。本轮名称调整按正常模式验证，签名Release单独发布。

## 决策

- 原生网络请求通过 src/api.ts 和受窗口权限约束的 Rust 适配器。核心与工具模块保持离线职责。
- 官方目录使用版本化 JSON，动作代码复用既有验证、限额及原子追加路径。
- 安装更新采用 Tauri 官方 updater 与固定发布公钥。私钥保存在忽略的 .local 目录。
- 自动检查在主窗口初始化后执行一次，手动点击可重试。
